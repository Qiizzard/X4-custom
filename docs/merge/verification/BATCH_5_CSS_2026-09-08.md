# Batch 5 — compound CSS verification, 2026-09-08 UTC

## Finding and fix

The inherited parser normalized each two-class key but interleaved bare and
tag-qualified matches for each pair of HTML classes. With `.m.n {bold}`,
`p.m.n {normal}`, `.m.o {bold}` and `<p class="m n o">`, the later bare match
incorrectly overrode the more specific tag rule. A new cold-parser assertion
reproduced this: simulator smoke exited 2 with `Cold compound CSS contract
failed` before the fix (/tmp/x4-batch5-red.log).

Resolution now applies all bare compounds before all tag-qualified compounds.
One reusable 256-byte key buffer replaces two simultaneously scoped buffers;
no new heap scratch is introduced. The existing eight-class-token cap bounds
pairs to 28 (56 lookups across the two passes). This is source-level resource
accounting, not a measured stack high-water mark or performance claim.

The test checks both HTML class orders and the non-p tag control, in addition
to the seven existing pair-order/tag/single-class/unsupported-selector checks.
All ten assertions run against cold and cached rules. A valid saved cache is
then altered only at its version byte to 16; loading must reject it. No test
passes merely because a cache fixture is truncated.

## Cache and fixture review

CSS_CACHE_VERSION is now 17: version 15 predates canonical pair keys, while
the local version 16 predates the corrected specificity ordering. The binary
layout is unchanged. Source inspection of Epub.cpp:719 confirms dependent
sections are removed after a complete CSS rebuild (or its existing eligible
partial-rebuild path); failed rebuilds preserve sections. The smoke proves
rule-cache rejection, not that entire section-invalidation workflow.

The fixture generator adds normal-weight tag-qualified examples in both
class orders plus a bold div control. Running it recreates
`test/epubs/test_css_compound_selectors.epub`. The generated EPUB is kept local;
the generator is the source artifact. Pixel appearance, images, fonts and
cold/reopened section equivalence remain hardware checks.

This is intentionally bounded parser support: selectors with three or more
compound classes remain unsupported; compound matching considers the first
eight HTML class tokens. Same-specificity matches retain the existing
resolver ordering rather than implementing a full CSS source-order cascade.
Pair-key normalization is order independent; this is not a claim of full
browser CSS conformance or order independence among every overlapping rule.
