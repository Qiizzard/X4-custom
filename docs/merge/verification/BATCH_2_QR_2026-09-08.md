## Memory review

The app limits input to 256 bytes. `src/util/QrUtils.cpp:30` selects version 4
through 114 bytes and version 10 above that limit. The installed QRCode source
uses ceil(side squared / 8) bitmap bytes: **137** at version 4 and **407** at
version 10. The payload bridge holds up to 257 character bytes including NUL;
allocator overhead and string capacity are additional. Truncation storage in
QrUtils is unused at this app's cap.

QRCode also allocates variable-length arrays on the render stack, despite the
wrapper's heap-buffer comment. In `qrcode.c:794`, `:818`, `:709`, and `:712`,
codeword, function-grid, error-correction-result, and coefficient arrays have
source-level payload totals of **359 bytes at version 4** and **1117 bytes at
version 10/ECC_LOW** (101+137+101+20 and 346+407+346+18). These are array-size
calculations, not measured stack high-water marks; call frames, alignment,
other locals and renderer work add to them. Reader render stack configuration
is 16384 bytes (`src/main.cpp:309`); this alone does not prove adequate margin.

The QR activity remains allocated while KeyboardEntry is pushed. KeyboardEntry
contains an in-object InteractionBuffer<48>, title/text strings and temporary
render/result strings. ActivityManager destroys the keyboard before invoking
the QR result handler (`src/activities/ActivityManager.cpp:128`), but moved
result text can remain live during that handler. A bitmap-only heap allowance
therefore does not establish the peak of the input/edit paths.

The previously recorded C3 activity-object measurement is 488 bytes. Its old
space-free build directory is no longer present; it was not remeasured here.
The 4096-byte manifest heap allowance remains an **unverified estimate**,
not a measured upper bound. No allocation or stack reduction is claimed.
QrUtils still uses throwing `std::make_unique`, and shared keyboard/string
allocations are also not uniformly fallible. Those shared-path failure modes
remain open for a separately scoped fix; no OOM injection was performed.
